# 项目接口约定

这份文档是五个开发分支共同遵守的字段约定。项目以在线招聘平台岗位采集为数据入口，字段先按这里实现，发现确实不够用时，由卢世豪审核后再改，不能在各自分支里单独改名。

## 1. 数据采集约定

- 首期目标平台为 BOSS 直聘，采集实现参考 `eatmoreduck/boss-zhipin-scraper`，通过 Chrome DevTools Protocol 被动读取页面自身返回的岗位列表数据；智联招聘、51job 等其他平台标记为待确认；
- 采集范围至少包括大数据、数据分析、数据开发、人工智能等相关岗位，并支持关键词、城市和岗位类型配置；
- 原始采集结果保存到 `data/raw/`，清洗脚本再输出 `data/processed/jobs.csv`，算法、服务和页面不直接读取原始采集结果；
- 每次采集保留平台名称、采集范围、采集时间、来源链接或来源说明、原始记录数和异常记录数；
- 采集模块支持手动触发、网站配置、启停、开始时间和每天一次或每天两次等批量采集频率，并预留按网站适配器进行水平扩展的边界；首期不承诺持续实时更新；
- 爬取流程必须提供深度优先和广度优先两种策略，策略选择和遍历过程需要有项目自研代码及运行记录；
- 采集只处理岗位信息，不采集个人简历、手机号、账号 Cookie 等个人敏感信息；BOSS 登录由使用者在独立浏览器用户目录中手动完成，不复制日常浏览器登录状态，不绕过登录、验证码或平台访问限制。平台规则不允许自动采集时，立即停止并记录原因；
- 采集脚本、原始文件和清洗结果都不得写入账号凭据、Cookie 或其他密钥。

大规模统计和挖掘优先使用 PySpark/Spark DataFrame，清洗和页面接口可以使用 pandas。无论使用哪种处理引擎，输出都必须转换为本文件规定的字段和返回结构。

## 2. 岗位数据表 `data/processed/jobs.csv`

CSV 的列名、含义和格式固定如下。`salary_min`、`salary_max`、`salary_avg` 统一使用人民币元/月，不能转换的值留空，不填 0。字段由多个平台的原始字段统一映射得到。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `job_id` | string | 是 | 岗位唯一标识，清洗后不重复 |
| `title` | string | 是 | 岗位名称 |
| `company` | string | 是 | 公司名称，缺失留空并记录异常 |
| `company_intro` | string | 否 | 公司介绍 |
| `company_size` | string | 否 | 公司规模 |
| `company_nature` | string | 否 | 公司性质 |
| `industry` | string | 否 | 所属行业 |
| `city` | string | 否 | 工作城市 |
| `work_type` | string | 否 | 全职、实习、校招、远程等 |
| `experience` | string | 否 | 经验要求，保留标准化后的文本 |
| `education` | string | 否 | 学历要求 |
| `skills` | string | 是 | 技能名称用英文分号 `;` 分隔，如 `Python;SQL;pandas` |
| `description` | string | 否 | 岗位描述，缺失留空 |
| `benefits` | string | 否 | 职位待遇和福利，多个项目用英文分号 `;` 分隔 |
| `salary_text` | string | 否 | 页面原始薪资文本 |
| `salary_min` | float | 是 | 月薪下限，缺失留空 |
| `salary_max` | float | 是 | 月薪上限，缺失留空 |
| `salary_avg` | float | 是 | 月薪平均值，缺失留空 |
| `source` | string | 是 | 招聘平台名称，首期固定为 BOSS直聘 |
| `source_url` | string | 否 | 岗位来源链接或来源标识 |
| `crawled_at` | string | 是 | 采集时间，使用 ISO 8601 格式 |

代码中的固定列名位于 `src/data/schema.py` 的 `JOB_COLUMNS`。卢世豪负责采集、字段解析和清洗输出，徐挚凌负责读取校验，郑维豪负责使用清洗后的数据完成算法分析。其他模块只读取清洗后的表，不直接读取原始数据。

### BOSS 原始字段映射

首期适配器接收上游脚本输出的 JSON 或 CSV，并按下表转换。上游列表数据没有的字段不得推测，详情采集成功后再补充。

| 上游字段 | 标准字段 | 处理规则 |
|---|---|---|
| `encrypt_job_id` | `job_id` | 作为平台岗位标识；缺失时记录异常 |
| `title` | `title` | 去除首尾空白 |
| `boss_name` | `company` | 上游该字段实际保存公司品牌名称 |
| `salary` | `salary_text` | 保留原文，再解析月薪上下限和平均值 |
| `location` | `city` | 按“城市·区县·商圈”拆分，标准表先保存城市 |
| `tags` | `experience`、`education` | 按经验和学历规则分别识别 |
| `skills` | `skills` | 将竖线分隔值统一为英文分号 |
| `welfare` | `benefits` | 将竖线分隔值统一为英文分号 |
| `company_scale` | `company_size` | 原样保留后再统一分类 |
| `company_industry` | `industry` | 原样保留 |
| `job_link` | `source_url` | 保存岗位详情链接 |
| 详情页 `jd` | `description` | 仅在详情采集成功时写入 |
| 无直接对应字段 | `company_intro`、`company_nature`、`work_type` | 留空并记录缺失，不从其他字段推断 |

`source` 固定写为 `BOSS直聘`，`crawled_at` 由本项目适配器在导入时写入 ISO 8601 时间。`security_id`、`lid`、招聘者信息和公司链接只保存在原始数据中，不进入标准岗位表。

## 4. 采集管理接口

网站配置至少包含以下字段：`site_id`、`site_name`、`base_url`、`enabled`、`keywords`、`cities`、`crawl_strategy`、`start_at`、`frequency` 和 `max_depth`。首期配置使用 `site_id=boss_zhipin`、`site_name=BOSS直聘`。`crawl_strategy` 只能是 `bfs` 或 `dfs`，`frequency` 支持每天一次、每天两次等可配置频率。

徐挚凌负责提供网站列表的新增、查询、修改、删除、启停和采集任务触发接口。卢世豪负责各网站采集适配、字段解析和 BFS/DFS 自研遍历逻辑。郑维豪负责分析输入校验和算法输出。不同网站的适配代码不能互相复制页面解析规则，新增网站应只增加对应适配模块并复用调度流程。

采集任务至少记录：`task_id`、`site_id`、`started_at`、`finished_at`、`status`、`raw_count`、`parsed_count`、`error_count` 和 `error_message`。

## 5. 服务层接口

```python
filter_jobs(jobs, filters) -> pandas.DataFrame
summarize_jobs(jobs) -> dict
```

`filters` 允许以下键：`keyword`、`city`、`work_type`、`experience`、`education`、`industry`、`company_nature`、`salary_min`、`salary_max`。筛选函数返回岗位表的标准列，且不修改输入数据。无结果返回空表，不抛出异常；字段缺失或筛选键错误才抛出明确错误。

`summarize_jobs` 返回以下键：`job_count`、`salary_count`、`salary_min`、`salary_max`、`salary_avg`、`top_skills`。其中 `top_skills` 是按次数排序的 `(技能, 次数)` 列表。

## 6. 分析和推荐输出接口

| 模块 | 输出列或键 | 负责人 |
|---|---|---|
| KMeans 聚类 | 原岗位字段 + `cluster_id`；群组说明另以字典返回 | 郑维豪 |
| 随机森林薪资预测 | 原岗位字段 + `predicted_salary`；指标键为 `mae`、`r2` | 郑维豪 |
| TF-IDF 推荐 | `job_id`、`title`、`company`、`city`、`similarity_score`、`matched_skills`、`missing_skills`、`reason` | 丁伟哲 |
| 薪资因素分析 | `factor`、`impact_direction`、`importance`、`description` | 郑维豪 |
| 岗位能力需求图谱 | `nodes`、`edges`、`skill_frequency` | 郑维豪 |
| 企业画像 | `company`、`company_size`、`company_nature`、`industry`、`salary_summary`、`skill_summary` | 郑维豪 |
| 求职者画像与多因素推荐 | `job_id`、`title`、`company`、`company_size`、`company_nature`、`industry`、`salary_range`、`match_probability`、`matched_skills`、`missing_skills`、`reason` | 丁伟哲 |

算法模块只接收清洗后的岗位表和固定画像，不读文件、不调用 Streamlit。页面不重新实现算法，只展示返回结果。学校、专业、学历、工作年限和工作经历等求职者因素用于画像分析和匹配计算；分析结果描述数据中的关联，不表述为因果结论。

## 7. 联调顺序

1. **采集基线**：卢世豪提交 BOSS 采集范围、上游项目复现记录、网站配置、BFS/DFS 运行记录、原始数据和采集任务记录；郑维豪审核分析所需字段。其他平台是否接入在该节点确认。
2. **清洗基线**：卢世豪提交 `jobs.csv`、数据字典和清洗运行记录；郑维豪审核字段、单位和特征可用性。
3. **分析基线**：郑维豪完成薪资因素、岗位能力需求图谱、企业画像、KMeans 和随机森林的样例输出；丁伟哲完成求职者画像和多因素推荐样例。
4. **服务基线**：徐挚凌接入网站管理、采集任务、筛选、统计和算法调用，统一错误状态。
5. **页面联调**：王宇杰接入管理、分析和推荐页面，全组用同一份采集数据走通演示链路。

每个阶段先在个人分支完成验证，再由卢世豪审核并合并到 `main`。没有通过上一阶段的分支，不进入下一阶段联调。
