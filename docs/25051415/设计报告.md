# 设计报告

> 项目：面向大学生求职的岗位数据分析与个性化推荐系统
> 撰写：丁伟哲（25051415）｜整理日期：2026-09-06

## 一、设计目标与原则

面向实习和校招大学生，解决岗位信息分散、待遇难比较、求职方向难判断的问题。系统以 BOSS 直聘大数据相关岗位为首期数据源，完成"采集 → 清洗 → 分析建模 → 个性化推荐 → 可视化展示"的完整链路。设计遵循四条原则：

1. **可解释**：算法输出附带理由、匹配/缺失技能、口径说明，不用黑箱；
2. **可复现**：真实数据复算脚本与结果快照入库，测试可一键运行；
3. **接口冻结、并行开发**：岗位表、画像、输出契约先冻结，五人按分支独立开发；
4. **数据合规**：只采集公开岗位信息，不采集手机号、简历、Cookie，不绕过平台限制。

## 二、需求分析与功能设计

**角色与用例**

- 求职学生：浏览市场概览与岗位检索；填写求职画像，获得个性化推荐与理由；
- 管理员：维护采集网站配置，管理采集任务（启停、频率、触发）、查看任务记录。

**功能需求**

| 模块 | 功能 | 设计要点 |
|---|---|---|
| 采集（卢世豪） | BOSS 岗位采集、BFS/DFS 任务遍历 | 上游项目固定版本 + 独立 Chrome 用户目录手动登录；遍历策略可配置 |
| 清洗（卢世豪） | 字段统一、去重、缺失标记、薪资/地区标准化 | 输出 21 列标准岗位表；清洗前后数量、缺失、异常可说明 |
| 分析洞察（郑维豪） | 薪资因素分析、能力需求图谱、企业画像、KMeans 聚类、随机森林薪资预测 | 输出字段冻结；正常与异常案例齐备 |
| 个性化推荐（丁伟哲） | 画像输入、基线推荐、多因素推荐 | 输出契约冻结；结果随画像变化、可解释 |
| 服务层（徐挚凌） | 网站配置、任务调度、岗位检索统计、算法调用封装 | 页面不直接读原始数据、不重复实现模型逻辑 |
| 展示层（王宇杰） | Streamlit 五模块页面 | 一条命令启动；异常状态有提示 |

**非功能需求**：异常/空数据不崩溃且有明确提示；结果不写死（输入变化输出变化）；测试可自动发现运行；GitHub Actions 持续集成；大体积数据与课程记录分仓库路径管理。

## 三、总体架构设计

```
展示层    Streamlit 五模块(市场概览/岗位检索/分析洞察/个性化推荐/采集管理)
服务层    site_service | task_service | job_service | analysis_service
算法层    薪资因素/技能图谱/企业画像 | KMeans | 随机森林 | TF-IDF+多因素推荐
数据层    data/processed/jobs.csv(21 列标准岗位表)+ fixtures 可复现样例
清洗层    字段映射/去重/空值标记/薪资与地区标准化(卢世豪)
采集层    boss 适配器(CDP) + BFS/DFS 自研遍历(卢世豪)
```

数据单向向下游流动，下游只消费标准岗位表与冻结契约，不反向依赖上游细节；算法层不直接读文件，页面不直接读原始数据。分层保证任意模块可先用独立样例开发、最后集中联调。

## 四、数据设计

**岗位数据表**（`JOB_COLUMNS`，与《接口约定.md》第 2 节一致，21 列）：`job_id`、`title`、`company`、`company_intro`、`company_size`、`company_nature`、`industry`、`city`、`work_type`、`experience`、`education`、`skills`、`description`、`benefits`、`salary_text`、`salary_min`、`salary_max`、`salary_avg`、`source`、`source_url`、`crawled_at`。其中 9 项必要字段（`REQUIRED_JOB_COLUMNS`）在输入校验时强制，其余列缺失时按空值处理。

**薪资口径设计（终态）**：以 `salary_text` 为唯一解析依据，只解析明确的人民币月薪；时薪、日薪、周薪、年薪、计件、面议与单位不明保留原文并置空数值列，不按金额猜测单位。算法层只接收标准化后的 `salary_avg`，仅保留 `<500` 元/月低值兜底标记，不设置 `>100000` 硬删阈值——高薪样本保留并参与分析。口径验证含三类断言并随真实数据复算（`tests/verify_salary_real_data.py`）。

**求职者画像**（`StudentProfile`，11 字段）：`target_role`、`education`、`major`、`school`、`skills`、`preferred_city`、`work_years`、`work_experience`、`expected_salary_min`、`expected_salary_max`、`experience`。`experience`（如"在校生/应届"）与岗位表 experience 列包含匹配；`work_years`、`work_experience`、`school` 写入画像说明，不直接参与岗位匹配。

**数据规模与版本**：真实岗位快照 19,988 条（有效薪资 18,946、缺失 1,042），复算脚本与结果存 `tests/fixtures/`；个人开发用可复现小样例（`sample_jobs.csv` 等），大体积数据不入库主路径（`data/processed/` 由 .gitignore 忽略）。

## 五、算法设计（重点：个性化推荐，丁伟哲）

### 5.1 文本表示与相似度

- 岗位侧文本：`title + skills + description + company`；画像侧文本：`target_role + skills + preferred_city + experience`；
- `TfidfVectorizer(analyzer="char_wb", ngram_range=(2,3))`：字符级 n-gram 免分词，中文与英文技能名均有效；IDF 降低常见字符权重；
- 相似度用余弦相似度，只关心文本方向接近程度，不受文本绝对长度影响；
- 无可比文本（画像为空且技能为空、岗位文本全空）时返回空结果而非报错。

### 5.2 基线推荐 `recommend_jobs`

排序分 `combo = 余弦相似度 + 0.2×技能F1 + 0.1×城市命中 + 0.05×经验命中`，输出 8 列（`RECOMMENDATION_COLUMNS`：job_id、title、company、city、similarity_score、matched_skills、missing_skills、reason），供联调契约使用。

### 5.3 多因素推荐 `recommend_jobs_multifactor`

权重冻结于 `WEIGHTS`（和为 1）：

| 因素 | 权重 | 计算方式 |
|---|---|---|
| 文本相似度 | 0.35 | 目标岗位名对岗位文本的 TF-IDF 余弦 |
| 技能命中 | 0.25 | 对称 F1：recall=命中/画像技能，precision=命中/岗位技能，惩罚岗位附带大量无关技能 |
| 薪资区间 | 0.15 | 期望区间与岗位区间取交集判定；期望未填取中性，岗位缺失不加分 |
| 城市 | 0.10 | 画像城市包含于岗位城市 |
| 经验 | 0.05 | 经验状态文本包含匹配 |
| 学历 | 0.05 | 画像学历包含于岗位学历要求 |
| 专业 | 0.05 | 专业名出现在标题/技能/描述/公司文本 |

`match_probability = clamp(组合分, 0, 1)`（保留 3 位）作为 0–1 匹配概率展示；输出 11 列（`MULTI_FACTOR_RECOMMENDATION_COLUMNS`，含 salary_range、company_size、company_nature、industry）。只校验 9 项必要列，可选列缺失按空补齐，不中断推荐。

**岗位族约束 `_restrict_to_role`**：当岗位表存在目标岗位族命中时只在族内排序（先按完整标题、再去掉"工程师/专员/经理"等常见后缀匹配族名）；族样本过稀时退化为按领域大类（`job_category`）筛选；两关都不足则保留全量参与打分，避免新岗位命名导致无结果。

**推荐理由 `reason`**：拼装"岗位文本相似度、匹配技能、缺失技能、城市符合期望、经验/学历/专业匹配、薪资区间符合或低于期望、画像（学校/年限/经历）"等片段——用户能逐条看懂推荐依据；薪资低于期望的岗位不删除，仅在理由中明示，把权衡交给用户。

**异常设计**：空岗位表/空画像 → 返回空表；缺必要字段 → 抛出含缺失列名的明确错误；无任何有效画像字段 → 空表；TF-IDF 无文本 → 空结果。均不崩溃。

### 5.4 其他算法模块（简述，负责人见架构图）

郑维豪：薪资因素分析输出 `factor/impact_direction/importance/description`；技能图谱输出 `nodes/edges/skill_frequency`；企业画像输出公司维度薪资与技能摘要；KMeans 聚类（特征标准化、群组标签与说明，样本不足报错）；随机森林薪资预测（独立训练/测试划分，输出 MAE 与 R²，样例 MAE≈3416.67、R²≈0.7635；真实数据指标以复算脚本快照为准）。算法均基于清洗后 `salary_avg` 等标准列，与薪资口径终态一致。

## 六、服务层与页面设计

**服务层**（徐挚凌）把数据与算法封装为页面可调用函数，页面不直接读文件：

- `site_service`：网站配置增删改查、启停、采集频率与开始时间校验；
- `task_service`：采集任务手动触发、状态/记录查询、下次计划时间计算；
- `job_service`：岗位读取、按 `FILTER_KEYS`（keyword/city/work_type/experience/education/industry/company_nature/salary_min/salary_max 共 9 键）筛选、数量/技能频率/薪资分布统计、空数据与缺文件提示；
- `analysis_service`：封装主题分析、聚类、薪资预测与推荐函数，统一返回契约。

**页面**（王宇杰）：Streamlit 五模块——市场概览（KPI、高频技能、城市分布）、岗位检索（筛选 + CSV 下载 + 详情）、分析洞察（薪资分布与因素、能力图谱、企业画像、聚类、薪资预测）、个性化推荐（画像表单 + basic/multifactor 双模式 + `st.session_state` 保存状态）、采集管理（站点与任务管理）。前端按《前端设计说明》统一视觉规范，输入变化驱动结果变化。
