# 我的工作：

在本次软件开发实践的短学期项目中我承担了较多的工作。我首先主导了立项，将选题确定为#面向大学生求职的岗位数据分析与个性化推荐系统。事实上我原本对于金融数据分析及可视化这个选题更加感兴趣，但考虑到我们组对于金融领域并不熟悉就弃选了。

对于项目架构的设计我首先是和ai提了我的需求，它给了一份方案给我自己审查了我了解的技术栈，把前端技术栈确定为了streamlit这个框架，因为之前做过类似的python项目，对于这个框架还算是熟悉的。考虑到这个项目主要是数据的可视化，并不需要太精美的前端，我没有选择vue，react这些框架。而且这门课也主要是要求python。

还有就是数据爬取的方案，我并没有让ai从零开始设计爬虫框架，我是直接到github上搜索了boss直聘到爬虫工具，很快就找到适合我们项目的，我就指挥ai接入了我们的项目中。很快就爬取到了数量和质量很可观的数据

在具体开发时首要的问题就是团队开发的协作问题。正式开始时，我就让组员赶紧准备好github账号和coding agent。教会他们使用git协作开发。新建分支，commit，push，创建PR，Review等一点一点教他们。除此之外我又写好AGENTS.md将项目规范固定下来，对他们的AI进行约束。通过各种文档，厘清每个人的任务，职责，验收和交付标准。截止笔者撰稿时我们的项目仓库共有256次commit，36个分支，合并53个PR。现在看来还是蛮有成就感的。

在使用AI coding时，还是会出现很多问题的。比如你没有说清楚需求一昧让他写代码，很快就会出现幻觉，偏离方向。一个真实的例子就是，起初我们对git不熟悉，开发时没有注意拉取最新main分支的改动，就在自己的工作分支上一直写下去，很快就出现接口不一致。企业和用户画像的每个人写的代码里字段不统一等等问题。所以我就在AGENTS.md上明确制定了，提交或者创建PR前一定先拉取最新改动，解决冲突。这些东西你不说，有时候AI真的会忘记。还有就是在采集数据时，可能是AI有长期记忆的原因，他爬数据就只爬取和计算机有关的岗位，而且不知道为啥只爬取上海和杭州两个城市，于是我又停下来和他说，职业领域要扩大，地域也要扩大，把AI的方向扭正。

写前端的同学做出来的页面太简陋，我看不下去，我又帮他重新设计。我让AI了解下我们的项目，简单提了几个需求。让他先调用gpt-image-2出几个设计图，给我挑选。由于之前觉得superpowers这一套skill太重了，占上下文、费token。就删除了。他没有继续追问我更多的需求。没办法为了保证质量，我又堆叠了frontend-design、taste-skill等skills，出来的图还行，由于这是一个数据分析项目我并没有追求更多的花里胡哨。就定了这一张。

![](assets/前端设计稿-v1.png)

看着还行，接下来我又用image-to-code这个skill转换成真实前端代码。我还担心steamlit这个框架不能很好复现，问AI需要引入css、react吗。AI说不用。但我还是做了更多尝试。比如通过figma MCP让AI转换成figma的设计稿文件，这样可以更精确的做修改，提高复原程度。但由于我没有订阅，figma MCP的额度很快用完，最后制作出两个页面的设计稿，这个计划暂时搁置。

最后出乎我的意料，直接通过图片复原程度也挺高的，可能是因为这个项目的前端本来就不需要过度设计，也可能是一开始生成的图就已经很“AI”了。

# 我的感受 ：

说实话，这门课算是很接近真实企业开发的了。总比之前整天念PPT的水课强。一个是老师间接倒逼我们真实的使用AI开发项目，逼我们学会使用git开发，这些是真正在工作会用到的，我深有所感。还有一个就是写日报这个确实有股“班味了”

AI Coding是未来的趋势，但这并不意味着我们就不用学了。相反，我们学的要比以前更多，既要懂以前传统的计算机基础。你要懂什么是CPU、GPU，懂缓存、内存、显存、磁盘，懂IP，DNS，http协议，不让就像本次项目实践，老师让发局域网网址，你发个localhost，那不是让人笑话吗？

还要懂怎么更好的使用AI。AI很强大，但你不会用就是废铁。我真实的感受就是，同一个模型，人家写的前端那么好看炫酷，我写的一股AI味儿。。。。。
