# 项目接口约定

这份文档是五个开发分支共同遵守的字段约定。项目以在线招聘平台岗位采集为数据入口，字段先按这里实现，发现确实不够用时，由卢世豪审核后再改，不能在各自分支里单独改名。

## 1. 数据采集约定

- 首期先选择一个平台、一个岗位方向和明确的城市或关键词范围，先跑通可重复的采集闭环，不同时开发多个平台；
- 原始采集结果保存到 `data/raw/`，清洗脚本再输出 `data/processed/jobs.csv`，算法、服务和页面不直接读取原始采集结果；
- 每次采集保留平台名称、采集范围、采集时间、来源链接或来源说明、原始记录数和异常记录数；
- 采集只处理岗位信息，不采集个人简历、手机号、账号 Cookie 等个人敏感信息；不得绕过登录、验证码或平台访问限制。平台规则不允许自动采集时，先停止并报告，不擅自更换方式；
- 采集脚本、原始文件和清洗结果都不得写入账号凭据、Cookie 或其他密钥。

## 2. 岗位数据表 `data/processed/jobs.csv`

CSV 的列名、含义和格式固定如下。`salary_min`、`salary_max`、`salary_avg` 统一使用人民币元/月，不能转换的值留空，不填 0。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `job_id` | string | 是 | 岗位唯一标识，清洗后不重复 |
| `title` | string | 是 | 岗位名称 |
| `company` | string | 否 | 公司名称，缺失留空 |
| `city` | string | 否 | 工作城市 |
| `work_type` | string | 否 | 全职、实习、校招、远程等 |
| `experience` | string | 否 | 经验要求，保留标准化后的文本 |
| `education` | string | 否 | 学历要求 |
| `skills` | string | 是 | 技能名称用英文分号 `;` 分隔，如 `Python;SQL;pandas` |
| `description` | string | 否 | 岗位描述，缺失留空 |
| `salary_min` | float | 是 | 月薪下限，缺失留空 |
| `salary_max` | float | 是 | 月薪上限，缺失留空 |
| `salary_avg` | float | 是 | 月薪平均值，缺失留空 |
| `source` | string | 否 | 招聘平台、授权接口或数据集来源名称 |

代码中的固定列名位于 `src/data/schema.py` 的 `JOB_COLUMNS`。郑维豪负责采集和清洗输出，徐挚凌负责读取校验。其他模块只读取清洗后的表，不直接读取原始数据。

## 3. 学生画像 `StudentProfile`

画像在代码中使用 `src.data.schema.StudentProfile`，页面或服务层传入字典时使用下面的键名：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `target_role` | string | 空字符串 | 目标岗位或关键词 |
| `skills` | tuple[string, ...] | 空元组 | 已掌握技能；字典输入也可用 `Python;SQL` 字符串 |
| `preferred_city` | string | 空字符串 | 期望城市 |
| `experience` | string | 空字符串 | 经验情况 |
| `expected_salary_min` | float or None | None | 期望月薪下限 |
| `expected_salary_max` | float or None | None | 期望月薪上限 |

丁伟哲负责推荐计算，王宇杰负责页面控件，二者都只使用这些键名。

## 4. 服务层接口

```python
filter_jobs(jobs, filters) -> pandas.DataFrame
summarize_jobs(jobs) -> dict
```

`filters` 只允许以下键：`keyword`、`city`、`work_type`、`experience`、`salary_min`、`salary_max`。筛选函数返回岗位表的标准列，且不修改输入数据。无结果返回空表，不抛出异常；字段缺失或筛选键错误才抛出明确错误。

`summarize_jobs` 返回以下键：`job_count`、`salary_count`、`salary_min`、`salary_max`、`salary_avg`、`top_skills`。其中 `top_skills` 是按次数排序的 `(技能, 次数)` 列表。

## 5. 算法输出接口

| 模块 | 输出列或键 | 负责人 |
|---|---|---|
| KMeans 聚类 | 原岗位字段 + `cluster_id`；群组说明另以字典返回 | 卢世豪 |
| 随机森林薪资预测 | 原岗位字段 + `predicted_salary`；指标键为 `mae`、`r2` | 卢世豪 |
| TF-IDF 推荐 | `job_id`、`title`、`company`、`city`、`similarity_score`、`matched_skills`、`missing_skills`、`reason` | 丁伟哲 |

算法模块只接收清洗后的岗位表和固定画像，不读文件、不调用 Streamlit。页面不重新实现算法，只展示返回结果。

## 6. 联调顺序

1. **数据基线**：郑维豪提交采集范围、数据来源、采集记录、原始数据说明、`jobs.csv`、数据字典和清洗运行记录；卢世豪审核字段和单位。
2. **算法基线**：卢世豪、丁伟哲分别提交正常案例和空数据案例；徐挚凌只接固定函数签名。
3. **服务基线**：徐挚凌提交筛选、统计和模型调用示例；卢世豪审核返回字段。
4. **页面联调**：王宇杰接入服务层，不直接改算法和数据清洗代码；全组用同一份数据走通演示链路。

每个阶段先在个人分支完成验证，再由卢世豪审核并合并到 `main`。没有通过上一阶段的分支，不进入下一阶段联调。
