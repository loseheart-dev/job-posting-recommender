# 组员报告：后端数据服务与联调：徐挚凌

## 一、整个项目是什么

项目通过在线招聘平台采集岗位数据，使用 PySpark/Spark 完成大规模处理，为大学生提供岗位检索、市场分析、薪资预测和个性化推荐。卢世豪负责岗位采集、字段解析和清洗；郑维豪负责三类主题分析和模型；丁伟哲负责求职者画像和个性化推荐；我负责网站列表管理、采集调度、数据服务和模块联调；王宇杰负责页面。我负责把这些部分接起来，让前端通过稳定的函数获得数据和算法结果，而不是各自读取文件、重复写逻辑。

## 二、我的职责

- 提供网站列表新增、查询、修改、删除、启停，以及采集开始时间和频率配置；
- 提供采集任务触发、运行状态、成功数、失败数和错误信息查询；
- 首期接入卢世豪提供的 BOSS 适配器，通过统一接口支持其他网站后续扩展；
- 封装统一的数据读取、筛选和统计函数；
- 连接清洗数据、KMeans、随机森林和 TF-IDF 推荐模块；
- 约定函数输入、返回字段和错误提示；
- 处理模型未加载、数据为空、筛选无结果等情况；
- 先用固定返回样例验证服务接口，阶段审核通过后参加集中联调；
- 负责最终启动说明和从数据到页面的完整演示。

我不负责重写算法核心，不负责替换 Streamlit 或新增大型后端框架。当前项目采用轻量函数调用即可，但采集管理、任务调度、PySpark 数据处理接入和不同网站采集器接入必须能够完成要求中的基本演示。

## 三、我的交付物

1. 网站配置和采集任务管理服务；
2. 采集任务状态和运行记录服务；
3. 数据读取函数；
4. 岗位筛选和基础统计函数；
5. 三类分析和推荐的调用适配；
6. 统一的返回数据结构和错误提示；
7. 联调记录：输入、输出、页面表现；
8. README 中的安装、启动和演示步骤；
9. 从采集到推荐结果的完整案例。

## 四、验收标准

- 前端不直接读取原始数据，统一调用数据服务；
- 管理员可以管理网站列表、启停采集任务并设置开始时间和频率；
- BOSS 适配器可以按统一接口触发，手动任务和每天一次/每天两次的定时任务共用同一流程；新增网站不需要重写调度流程；
- 岗位关键词、地区、学历、经验、工作方式、行业和薪资筛选能实际改变结果；
- 统计、薪资因素、能力需求图谱、企业画像和推荐都能从统一入口调用；
- 数据文件不存在、采集失败、模型文件缺失、筛选无结果时页面不崩溃；
- 新成员按 README 能启动项目；
- 至少有一个完整正常案例和一个空数据/异常案例；
- 只合并已经运行验证的分支；
- 我本人能解释调用链、错误处理和模块边界。

## 六、明天答辩怎么讲

### 一分钟讲解

“我负责采集管理、后端数据服务与联调。我的工作是管理网站列表和采集任务，把采集结果、清洗数据和算法结果封装成前端可以稳定调用的函数。管理员可以设置网站、开始时间和频率，系统记录任务状态；用户输入筛选条件或求职者画像后，服务层返回分析和推荐结果。系统对采集失败、文件缺失、模型未加载和无筛选结果都有提示。”

### 可能被问的问题

**问：为什么不直接在 Streamlit 页面里写所有逻辑？**

答：页面只负责输入和展示，网站配置、采集任务、数据读取、筛选和模型调用集中在服务函数中，便于测试、复用和说明个人分工，也避免前端重复读原始数据。

**问：如果模型没有训练好，页面怎么办？**

答：页面提示模型未加载；推荐功能可以使用已保存模型或基础规则排序作为降级方案，并明确标注，不伪造模型结果。

**问：你的后端亮点是什么？**

答：亮点是把数据、算法和页面连接成可运行链路，并处理空数据、缺文件和无结果等异常，而不是只让单个 Notebook 跑通。
