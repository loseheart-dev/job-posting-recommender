## 第一步：把 GitHub 仓库克隆到本地

1. 打开 GitHub 上你们小组的仓库页面，点绿色 **Code** 按钮，复制 HTTPS 链接（形如 `https://github.com/小组名/仓库名.git`）
2. 打开 VSCode，按 `Ctrl+Shift+P` 打开命令面板，输入并选择 **Git: Clone**
3. 粘贴链接，选择本地保存位置（比如 `C:\Users\silen\Desktop`），VSCode 会自动克隆并提示打开文件夹

或者直接在终端里用命令行：

```bash
cd 想存放的目录
git clone https://github.com/小组名/仓库名.git
```

## 第二步：日常协作流程（每次开发都这样做）

小组协作的核心是：**先拉取最新代码 → 修改 → 提交 → 推送到远端**。

```bash
# 1. 拉取远端最新代码（开始工作前必做！）
git pull

# 2. 修改你的代码...

# 3. 查看改动了哪些文件
git status

# 4. 添加改动（用 git add . 添加全部）
git add 文件名

# 5. 提交，写清楚你改了什么
git commit -m "feat: 添加岗位数据清洗模块"

# 6. 推送到 GitHub
git push
```

VSCode 里的可视化操作：左侧边栏的 **源代码管理** 图标（圆圈分支图标），可以查看改动、输入提交信息、点 ✓ 提交、点同步按钮推送。

## 第三步：小组协作的几条关键建议

1. **开始工作前先 `git pull`**——不拉就改，很容易和别人改同一个文件产生冲突
2. **发生冲突时**：VSCode 会高亮显示冲突区域，有「接受当前更改 / 接受传入更改 / 两者都保留」三个按钮可选，处理完记得 commit 一次
3. **数据文件不要提交**：岗位数据（Excel/CSV）通常较大，建一个 `.gitignore` 文件忽略它们和 Python 虚拟环境：

```
# .gitignore 文件内容
__pycache__/
venv/
*.csv
*.xlsx
data/
.idea/
.vscode/
```

4. **建议约定分支**：每个人在 `main` 之外的开发分支上工作（如 `git checkout -b feature-recommend`），功能完成后合并回主分支，避免互相踩踏

## Claude

PR = **Pull Request（拉取请求）**，是 GitHub 上**请求把你的分支代码合并进另一个分支**的正式流程。

## 用白话讲

你写完代码、推到自己的分支后，不能自己直接改 `main`（项目规范也禁止）。你在 GitHub 上发起一个 PR，相当于说：

> "我 `feat/dingweizhe-recommendation` 分支上的改动已经完成并测试过了，请组长审查，通过后合并到 `main`。"

## 为什么小组开发要用 PR

1. **代码审查**：组长（卢世豪）合并前能逐行看你的改动，按验收清单检查，而不是悄悄堆进 main
2. **留下记录**：谁改了啥、为什么改、什么时候合并，全程可追溯
3. **讨论空间**：有问题直接在 PR 下面评论，比群里刷屏清晰

## 流程（对应你们的验收规范）

```
push 个人分支 → 在 GitHub 仓库页点 "Compare & pull request"
→ 写标题和说明（改了啥、怎么验证）
→ 卢世豪 review + 验收 → 合并到 main
```
