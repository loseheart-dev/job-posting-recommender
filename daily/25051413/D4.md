## 遇到的问题与解决
- 时薪"元/时"未折算导致 salary_avg 出现 12.5 低值：我最初建议清洗层按 8×21.75=174 工时折算，实测发现会把兼职时薪和疑似月薪误标（"Python 4900-5000元/时"→86 万/月）过度折算，R² 反而跌到 -0.6789。解决手段：①写 Python 实验脚本（pandas + sklearn）在 8608 行真实数据上对比"无条件×174 / 加高值上限剔除 / 只保留明确月薪"三种方案的 MAE 与 R²，量化过折算影响；②用 AI（豆包）审查团队 PR 并给出替代方案建议；③在 PR 上与卢世豪对齐，他采用"只解析明确月薪、非月薪记录保留原文并置空"的方案；④我再用 clean_jobs_with_report 重洗 + predict_salary 实测确认 R² 恢复到 0.1943。
- company_nature 100% 缺失：解决手段：①用 Python 解析 boss_sample.json / boss_details_sample.json 的原始字段结构，确认列表和详情接口都只有 company_scale/company_industry，没有"公司性质"字段；②读 cleaner.py / boss_adapter.py 源码核对字段映射链，判定为源头缺失而非清洗不彻底；③由算法层兜底输出"未知"，并在数据字典中标注为已知限制。
- 审查 PR 时发现 GitHub 展示的提交数与本地分支差异：解决手段：①用 gh CLI（gh pr view --json commits）核对 PR 在 GitHub 上的完整提交列表；②用 git fetch / git log 重新拉取分支，发现卢世豪已 push 第三个提交（8fc03e5 按薪资单位隔离非月薪记录），更新本地引用后确认最新状态再合并。
