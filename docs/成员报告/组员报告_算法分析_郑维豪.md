# 组员报告：算法分析与模型实现：郑维豪

## 一、整个项目是什么

项目名称是“面向大学生求职的岗位数据分析与个性化推荐系统”。项目首期采集 BOSS 直聘的大数据相关岗位，经过卢世豪完成字段解析和清洗后，分析岗位薪资、技能需求和招聘企业特征，再结合求职者画像完成岗位推荐。算法只依赖统一岗位表，不依赖平台原始字段。

全流程为：

```text
在线招聘平台 → 卢世豪采集、解析与清洗 → 徐挚凌数据服务
→ 我的主题分析与模型 → 丁伟哲个性化推荐 → 王宇杰前端展示
```

我使用清洗后的岗位数据完成岗位工资影响因素、岗位能力需求图谱和招聘企业画像，并实现 KMeans 岗位聚类和随机森林薪资预测。丁伟哲负责求职者画像、多因素职位推荐和推荐解释，我不重复实现他的推荐模块。

## 二、我的职责

我负责算法分析，具体包括：

1. 按《接口约定》准备包含标准字段、薪资缺失和样本不足情况的独立测试数据；
2. 固定薪资因素分析的输入字段、统计口径和输出结构；
3. 分析学历、经验、地区、技能、公司性质和公司规模等因素与岗位薪资的关系；
4. 统计岗位技能频率和技能共现关系，输出岗位能力需求图谱；
5. 按行业、公司性质、公司规模、薪资和技能需求聚合招聘企业信息，输出企业画像；
6. 使用 KMeans 根据岗位类别、技能、地区、经验和薪资等特征进行岗位聚类，解释每个岗位群组；
7. 使用随机森林回归预测岗位薪资，划分训练集和测试集，输出 MAE、R² 等指标；
8. 为徐挚凌提供稳定的分析函数、输入输出说明、评价指标和异常状态，供王宇杰页面展示。

我不修改采集、清洗和 Streamlit 页面，也不把训练集结果当成模型验证结果。开发阶段只依赖标准岗位表；发现接口无法表达的字段问题时记录数据证据和影响范围，交由卢世豪在阶段审核时处理。

## 四、验收标准

- 三类主题分析均使用卢世豪提供的清洗岗位数据，结果可以重新运行；
- 薪资因素输出因素名称、方向、重要性和说明，不把统计关联写成因果关系；
- 能力需求图谱包含技能节点、技能频率和共现关系；
- 企业画像包含企业性质、规模、行业、薪资和技能摘要；
- KMeans 输出每条岗位的 `cluster_id`，并能说明每个群组的主要特征；
- 随机森林使用独立测试数据，至少报告 MAE 或 R²，并能解释指标含义；
- 数据字段缺失、样本不足或薪资有效样本过少时，返回明确提示；
- 徐挚凌可以调用分析函数，王宇杰可以展示结果；
- 我本人能解释特征处理、模型选择、指标和数据限制。

### 真实数据复测结论（2026-09-05）

- **接口兼容**：五函数全量跑通、21 列字段对齐，接口层无需改代码；
- **能力需求图谱**：技能白名单降噪后 133 节点/1263 边（降噪前 5938 节点），Top5 为 Java/Python/MySQL/SQL/Spring；

- **随机森林**：新清洗规则重洗后 MAE=4968.90、R²=0.1943（真实数据噪声大，R² 低于样例 0.7635 属预期）。
数据质量问题（skills 噪声、时薪"元/时"未折算、company_nature 缺失）已完成定位与分工解决，详见 `daily/25051413/D4.md` 与验收记录。

## 六、明天答辩怎么讲

### 一分钟讲解

“我负责岗位数据的算法分析。卢世豪先从 BOSS 直聘采集并清洗岗位数据，我在统一字段的基础上完成三部分分析：用统计方法分析学历、经验、地区、技能和企业特征与薪资的关系；用技能频率和共现关系生成岗位能力需求图谱；按企业信息形成招聘企业画像。同时，我用 KMeans 对岗位进行分组，用随机森林预测岗位薪资，并报告测试集指标。我的算法不直接读取平台原始数据，字段缺失时会明确缩小分析范围。”

### 可能被问的问题

**问：薪资因素分析能否说明因果关系？**

答：不能。项目分析的是采集样本中的统计关联，用于比较不同学历、经验、地区、技能和企业特征的待遇差异，不把结果表述为严格因果结论。

**问：为什么选 KMeans？**

答：岗位群组没有现成标签，KMeans 适合做基础无监督分组，结构清楚，便于解释。会结合特征标准化和轮廓系数选择合适的聚类数量。

**问：随机森林预测薪资是否等于真实薪资？**

答：不等于。它只能反映当前采集样本中的统计关系。项目使用测试数据评价，并说明样本来源、缺失薪资、地区差异和模型限制。

**问：AI 写的算法代码你能解释吗？**

答：我会检查字段处理、训练和测试划分、预测输出及指标计算，运行正常和异常案例后再提交。答辩时可以说明每个特征的来源和模型结果的边界。
