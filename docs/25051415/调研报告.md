# 调研报告

> 项目：面向大学生求职的岗位数据分析与个性化推荐系统
> 调研人：丁伟哲（25051415）｜整理日期：2026-09-06

## 一、同类产品调研

| 调研对象 | 主要功能 | 数据与技术特点 | 对本项目的参考价值 |
|---|---|---|---|
| BOSS 直聘 | 职位搜索、企业与求职者直聊、实习/校招专区 | 岗位按职位、城市、薪资等条件组织；推荐排序规则未公开 | 作为首期数据来源，重点分析岗位、薪资、技能与企业字段 |
| 智联招聘 | 校招、实习、职位搜索与投递 | 岗位含职位、地区、学历、经验与企业信息，有求职竞争力测评 | 作为后续平台扩展对象与岗位字段差异比较 |
| 前程无忧 | 全职、实习、校招搜索与投递 | 岗位信息字段较全，按城市/行业组织 | 作为后续平台扩展和数据对比对象 |
| SteamLens（同届对比组） | Steam 游戏标签/评论分析与内容推荐 | 标签多热编码加余弦相似度，公式化权重 | 说明推荐类项目共性路线：清洗数据 + 文本/标签相似度，可解释是共同卖点 |

结论：主流招聘平台的核心价值在"沟通—投递"闭环，其推荐与排序算法普遍不公开，学生无法知道"为什么推给我"；平台按实时职位组织，历史薪资行情、技能要求的量化汇总反而稀缺。本项目不复制聊天与投递功能，而是采集限定范围的公开岗位信息，统一字段后做薪资、技能、企业特征的量化分析与可解释推荐，填补"选岗决策参考"这一信息差。

## 二、技术发展趋势调研

1. **数据获取与合规**：网页数据获取经历了静态抓取、渲染引擎（CDP 协议控制浏览器）到按平台规则授权取数的演进。我国《个人信息保护法》与平台访问规则对采集提出合规约束，主流做法是限定范围、尊重登录与频控、不采集个人信息。产业上各平台普遍提供官方招聘接口或认证服务，合规取数成为行业底线。
2. **岗位文本表示**：从 TF-IDF、词向量（Word2Vec）、上下文预训练模型（BERT 族）到大语言模型，文本匹配能力持续增强。大模型出现后，产业界开始用"简历解析 + 语义匹配 + RAG"做智能人岗匹配，但存在算力成本高、结果难解释、幻觉等问题。轻量可解释路线（TF-IDF/多热编码 + 余弦相似度）在课程与中小应用中仍是主流基线。
3. **个性化推荐**：内容推荐（画像—物品相似）、协同过滤（用户行为）、深度学习与图推荐各有适用场景。面向学生求职的冷启动问题是共性难点：新用户无行为记录时，内容相似与画像匹配是唯一可靠起点；可解释推荐（给出匹配理由）成为提升信任的关键设计。
4. **数据分析与建模**：KMeans 聚类、随机森林等经典方法在小样本、可解释场景中仍然稳健；模型评估强调独立训练/测试划分与真实数据复算，避免泄漏与写死结果。
5. **产业应用现状**：国家把高校毕业生就业摆在突出位置，各地人社部门和招聘平台积极引入"AI 就业服务"：智能岗位匹配、简历诊断、薪资行情发布等应用已进入日常服务。同时《互联网信息服务算法推荐管理规定》要求算法透明可解释、不搞歧视性推送，直接影响了人岗匹配产品的设计约束——可解释不是加分项而是合规要求。

## 三、技术项目调研

1. [boss-zhipin-scraper](https://github.com/eatmoreduck/boss-zhipin-scraper)：通过 Chrome DevTools Protocol 读取页面自身返回的岗位列表数据并输出 JSON/CSV。本项目固定其上游版本，在独立浏览器用户目录中手动登录，自行完成任务遍历（BFS/DFS）、字段映射与清洗，Cookie 与登录状态不进入仓库。
2. [scikit-learn](https://scikit-learn.org/)：TfidfVectorizer 提供字符级 n-gram 文本表示，免分词处理中文；KMeans、RandomForestRegressor 用于岗位聚类与薪资预测，均支持小规模可复现实验。
3. [Streamlit](https://streamlit.io/)：以最小代码把数据服务与算法结果组织为可视化页面，适合课程原型快速交付。
4. [Pandas](https://pandas.pydata.org/)：承担 21 列岗位表的清洗、统一与统计，数据规模（万级）下性能与开发效率平衡良好。

## 四、对比结论与思政心得

技术选型结论：首期以 BOSS 直聘为数据入口（上游可复现、字段适合分析），智联与前程无忧仅作后续扩展；文本路线采用"TF-IDF 字符 n-gram + 多因素加权"而非直接上大模型，原因是本数据规模下经典方法可复现、可解释、成本低，与"推荐理由必须能讲清楚"的需求匹配。整套系统按"上游适配器 + 自研遍历清洗 + 可解释算法 + 服务与页面分层"组织。

思政心得：开发过程让我对技术伦理有了具体认识。一是**数据合规与诚信**：项目只采集公开岗位信息，不采手机号、简历、Cookie；清洗遇到失败保留真实记录、不伪造数据、不绕限——课程反复强调的"过程真实"正是科研诚信在工程上的体现。二是**算法向善与防歧视**：在薪资清洗口径讨论中，我们坚持不按主观阈值删除高薪样本、不以学历与薪资做简单化过滤，尽量让分析呈现数据原貌；《算法推荐管理规定》所要求的透明可解释，我们通过推荐理由、匹配与缺失技能展示落到实处，避免"黑箱决定命运"。三是**技术服务于就业民生**：本项目的落脚点是帮助普通学生减少求职信息差，这正是"就业是最大的民生"在信息化场景中的一次小实践；作为软件专业学生，把个人能力用于降低信息不对称、服务青年就业，是我们应有的价值取向。四是**协作与制度**：五人五分支、接口冻结、双人 review 的工程纪律，让我体会到现代化软件生产是协作与信任的制度化产物，个人代码只是其中的一环。
