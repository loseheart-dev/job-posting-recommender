# 五人任务分工与验收清单

## 项目信息

- 项目名称：`面向大学生求职的岗位数据分析与个性化推荐系统`
- 组长：`卢世豪`
- 成员：`卢世豪`、`丁伟哲`、`郑维豪`、`徐挚凌`、`王宇杰`
- 指定验收人：组长 + 对应任务的另一名成员

卢世豪负责阶段审核、接口变更裁决、分支合并和最终演示组织，不代替其他成员开发模块。

组长本人分支的 PR 由徐挚凌或郑维豪担任第二验收人，合并前须在 PR 中保留该成员的 review 记录。

## 总体交付目标

项目最终必须能够完成一条完整链路：

```text
在线招聘平台数据采集 → 原始数据保存 → 数据清洗 → 算法分析 → 结果可视化 → 用户操作得到结果
```

每名成员都要有一个可以独立演示 1 至 2 分钟的成果。只负责“协助”“查资料”或“调用 AI”不算独立交付物。

## 必须实现的项目要求

以下内容属于基础版本必须实现的功能，创新功能在基础版本完成后再安排：

1. 首期采集 BOSS 直聘的大数据相关岗位信息，提取职位名称、职位待遇、职位描述、公司介绍、公司规模、公司性质、行业、学历、经验和技能等字段；平台未提供的字段保留缺失标记，其他平台待确认；
2. 支持网站列表增删改查、启停、采集开始时间和采集频率配置，并预留采集器水平扩展能力；
3. 支持深度优先和广度优先爬取策略，提供项目自研的遍历算法；
4. 完成薪资影响因素分析、岗位能力需求图谱和招聘企业画像；
5. 根据求职者学历、专业、学校、求职地、工作年限、技能、工作经历和岗位名称，输出待遇水平、个人待遇区间、适配公司、公司性质与规模、行业和匹配概率；
6. 完成职位数据获取与预处理、职位数据可视化分析、多元职位推荐模型、职位信息展示和个性化推荐系统。

大数据处理使用 PySpark/Spark 或其他开源大数据组件，pandas 作为清洗和小样本处理工具；采集、分析和展示必须形成可运行的平台链路。

基础功能完成后，才安排增加平台、持续监控、增量采集、趋势预测、复杂模型和基于反馈的推荐优化等创新功能。基础版本采用按需触发和定时批量采集，不把持续实时更新作为首期承诺。

## 已冻结的共享接口

为减少互相等待，岗位表、学生画像、筛选参数和算法返回字段统一写在《接口约定.md》中，代码实现位于 `src/data/schema.py`。

- 卢世豪负责在线岗位数据采集、字段解析、清洗、原始数据说明和按约定输出 `data/processed/jobs.csv`，不自行改列名；
- 郑维豪负责算法输出字段，审核清洗数据是否满足分析和建模要求；
- 徐挚凌负责把采集管理、固定字段和算法调用封装成服务函数；
- 丁伟哲和王宇杰分别使用固定的推荐输入和服务返回，不直接读取原始数据；
- 每个人直接按冻结接口独立开发；接口确实无法满足任务时提交变更说明，由卢世豪统一审核和同步。

开发阶段五条个人分支并行推进。缺少真实上游模块时，使用符合接口的小型测试样例完成本模块。接口可调用、正常和异常案例通过、运行说明完整且代码已提交后，由卢世豪进行阶段审核，再统一安排集中联调。

## 任务分工

每个人只修改自己的任务目录，不等待其他成员交付。共享接口不能在个人分支自行改名；确需变更时提交原因、影响字段和兼容方案，由卢世豪处理。

### 卢世豪：后端成员，负责在线岗位数据采集、字段解析和数据清洗

主要任务：参考 `eatmoreduck/boss-zhipin-scraper` 完成 BOSS 直聘采集适配，负责字段解析、BFS/DFS 任务遍历、原始数据保存、字段统一和数据清洗，为算法、服务和页面提供可追溯的岗位数据。

下一步小步骤：

1. 固定上游项目版本，在独立 Chrome 用户目录中手动登录并验证 BOSS 限定范围采集，记录关键词、城市、时间和访问规则；
2. 将上游 JSON/CSV 输出接入 BOSS 适配器，保存原始结果、来源、采集时间和任务记录；
3. 实现 BFS 和 DFS 两种自研任务遍历策略，按关键词、城市和待采集任务组织执行，记录访问节点和结果；
4. 按《接口约定》映射职位、薪资、地区、公司、学历、经验、技能、福利和详情字段；没有来源的字段留空并记录；
5. 完成字段统一、去重、空值标记、薪资和地区标准化，输出 `data/processed/jobs.csv`；
6. 编写数据字典和清洗记录，说明字段类型、单位、来源和缺失规则；
7. 用正常数据、空文件、缺字段和坏格式分别验证采集导入和清洗流程；
8. 提交字段、路径、规则和验证结果，达到联调门槛后由卢世豪安排数据接入。

交付物：BOSS 上游项目复现记录、BOSS 适配器、BFS/DFS 遍历代码、原始数据、字段解析规则、清洗脚本、`jobs.csv`、数据字典、处理记录和异常案例。

验收标准：BOSS 限定范围采集结果可以复现，或在平台限制导致失败时保留真实错误记录；BFS 和 DFS 均能运行并保留记录；核心字段有明确类型和来源；清洗前后记录数、重复数、缺失值和异常薪资可说明；原始数据不被覆盖；登录状态和 Cookie 不进入仓库；空文件、缺字段和坏格式有提示；郑维豪和徐挚凌能直接读取约定数据；本人能解释采集、解析和清洗规则。

### 丁伟哲：算法成员，负责求职者画像和多元职位推荐

主要任务：根据学历、专业、学校、求职地、工作年限、技能、工作经历和岗位名称构建求职者画像，结合岗位与企业特征完成多元职位推荐，输出待遇水平、个人待遇区间、适配公司、公司性质与规模、行业、匹配概率和推荐理由。

下一步小步骤：

1. 按《接口约定》的岗位字段和 `StudentProfile` 画像字段准备独立测试样例；
2. 在 `src/algorithms/recommender.py` 中完成岗位文本 TF-IDF 与余弦相似度计算；
3. 加入学历、地区、经验、技能和薪资等因素，固定推荐函数返回结构；
4. 输出待遇水平、个人待遇区间、适配公司、公司性质与规模、行业、匹配概率、匹配技能、缺失技能和推荐理由；
5. 准备技术岗、数据岗、技能为空三组画像，测试空岗位、缺失字段和筛选无结果情况，提交可调用函数、样例输出和个人验收记录。

交付物：`recommender.py`、求职者画像字段说明、多因素计算说明、3 组测试画像、待遇分析、Top-K 结果和推荐解释。

验收标准：学历、专业、学校、地区、工作年限、技能、工作经历或目标岗位变化时，排序、待遇区间或解释会变化；结果不是写死的；每条推荐包含岗位、待遇区间、公司画像、匹配概率、匹配技能和缺失技能；无结果时有提示；徐挚凌能调用，王宇杰能展示。

### 郑维豪：算法成员，负责三类主题分析、模型实现和算法结果说明

主要任务：使用卢世豪提供的清洗岗位数据，完成岗位工资影响因素分析、岗位能力需求图谱、招聘企业画像、KMeans 岗位聚类和随机森林薪资预测，为推荐和页面展示提供可解释的分析结果。

下一步小步骤：

1. 按《接口约定》制作包含岗位、学历、地区、经验、技能、公司和薪资字段的独立测试数据；
2. 固定薪资因素分析的输入字段、统计口径和输出结构；
3. 完成岗位工资影响因素分析，输出因素方向、重要性和说明；
4. 完成岗位能力需求图谱，输出技能节点、共现关系和频率；
5. 完成招聘企业画像，输出企业性质、规模、行业、薪资和技能摘要；
6. 完成 KMeans 岗位聚类，记录特征、群组数量和每组解释；
7. 完成随机森林薪资预测，划分训练集和测试集并记录 MAE/R²；
8. 用正常数据、缺字段、空数据和样本不足数据运行，给出结果或明确错误提示，提交可调用函数、样例输出和个人验收记录。

交付物：三类主题分析代码和结果、KMeans 聚类代码和群组解释、随机森林代码和测试指标、特征说明、异常案例、算法函数说明和运行记录。

验收标准：三类主题均有可复现输出；KMeans 能输出群组标签和群组解释；随机森林有独立测试集指标；输入字段缺失或数据不足时有提示；徐挚凌能调用，王宇杰能展示；本人能解释特征、方法、指标和局限。

### 徐挚凌：后端成员，负责采集管理、调度、数据服务和前后端联调

主要任务：把网站列表管理、采集任务调度、数据读取、岗位筛选、统计和算法调用封装成页面可以直接使用的服务函数，支持采集器按网站水平扩展并跑通完整链路。

下一步小步骤：

3. 实现 BOSS 采集任务的手动触发、开始时间、每天一次/每天两次频率、运行状态和记录查询，支持后续网站适配器接入同一调度流程；
4. 在 `src/services/job_service.py` 中完成岗位关键词、地区、学历、经验、工作方式、行业和薪资筛选；
5. 增加岗位数量、技能频率、薪资分布等统计函数，统一返回字段和空结果状态；

7. 使用固定返回样例验证服务调用，补充 README 启动步骤；阶段审核通过后再接入真实数据、算法和页面。

交付物：采集管理与调度服务、数据读取模块、服务模块、调用示例、任务运行记录、联调记录和 README 启动说明。

验收标准：管理员可以管理网站列表、启停采集任务并设置开始时间和频率；新增网站可以按统一接口接入；前端通过服务函数拿到数据；筛选条件会影响统计和算法输入；模型未加载、文件缺失、采集失败和筛选无结果时有明确状态；项目可从采集到页面结果走通一条演示链路。

主要任务：把网站列表和采集任务管理、岗位检索、市场统计、三类分析、求职者画像和个性化推荐做成可操作页面，确保输入变化能反映到结果。
