# 调研报告

## 一、同类产品调研

| 调研对象 | 主要功能 | 数据与技术特点 | 对本项目的参考价值 |
|---|---|---|---|
| [BOSS直聘](https://www.zhipin.com/) | 职位搜索、企业查看、校招和沟通 | 按职位、城市、行业组织岗位，推荐规则未公开 | 首期数据来源，重点分析岗位、薪资和企业信息 |
| [智联招聘](https://www.zhaopin.com/) | 校招、实习、职位搜索和投递 | 岗位包含职位、地区、学历、经验和企业信息 | 后续平台扩展参考对象 |
| [前程无忧](https://www.51job.com/) | 全职、实习、校招、职位搜索和投递 | 覆盖职位、薪资、地区、经验和企业信息 | 后续平台扩展参考对象 |

三个平台都能帮助用户搜索岗位，但平台内部推荐算法通常不公开，用户难以了解排序依据。本项目不复制聊天和投递功能，而是采集限定范围的公开岗位信息，统一字段后分析薪资、技能和企业特征，并用可视化页面展示结果。

## 二、技术项目调研

1. [boss-zhipin-scraper](https://github.com/eatmoreduck/boss-zhipin-scraper)：通过 Chrome DevTools Protocol 读取页面自身返回的岗位列表数据。本项目固定其版本，在独立浏览器用户目录中手动登录，再自行完成任务遍历、字段映射和清洗。
2. [Streamlit](https://streamlit.io/)：Python 数据应用快速开发框架，适合课程原型阶段的 Web 页面构建，能直接承载控件、表格和图表。
3. [Plotly](https://plotly.com/python/)：Python 可视化库，支持交互式图表，用于薪资分布、技能频率等数据展示。

## 三、对比与结论

BOSS 直聘适合作为首期数据入口，因为上游项目已经提供了可复现的浏览器数据读取方式。技术上采用"上游采集适配器 + 自研 BFS/DFS + 统一清洗 + 可解释算法 + Streamlit 展示"的路线，既复用了成熟工具，也保留了本项目自己的遍历、分析和页面部分。

## 四、思政心得

在项目实施过程中，我深刻认识到技术应用需要遵守平台规则和数据伦理。项目采集只处理岗位信息，不采集手机号、简历、Cookie 等敏感信息；采集受登录、验证码和平台访问规则影响时保留真实记录，不绕过限制。这让我理解到，技术能力越大，责任越大，作为未来的工程师，我们应该在追求技术创新的同时坚守法律和道德底线，保护用户隐私和数据安全。

## 五、我的贡献

作为前端成员，我在调研阶段主要负责：
- 对比 Streamlit 和传统前端框架的适用场景，确定以 Streamlit 作为快速原型开发方案
- 调研 Plotly 在数据分析类页面中的图表能力
- 参与确认前端设计规范中的色彩、布局和交互要求
- 根据调研结果确定页面不新增 React、动画库或 UI Kit 的技术边界
